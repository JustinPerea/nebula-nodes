# Commons runner integration decisions

- Compose the historical clean Claude/Codex profiles with current main instead of replacing entire runner modules. Keep Krea discovery events, subscription billing checks, process-group cancellation and Daedalus dispatch.
- Claude and Codex receive a bound private working directory, backend URL and per-turn identity. Inherited agent tokens are cleared; fresh tokens are passed only by the backend. Model and effort remain explicit, and Commons prompt knowledge is injected only with the strict activation flag.
- User MCP configuration is ignored. Each invocation loads only the backend-built `nebula_krea` bridge, whose two allowed tools provide read-only discovery. Its URL is validated as a loopback origin and contains no Krea credential.
- Derive the Krea vault directory from the state root and deny that directory with the Commons store and settings files. Do not import the connector to discover its path, because constructing a connector can initialize real storage.
- Keep ordinary Daedalus unchanged while Commons is disabled. Enabled Commons, or a request to give Daedalus scoped authority, fails before native launch: the existing Hermes profile has no verified private file boundary. This is an explicit activation limitation, not proof of Daedalus isolation.
- The CLI forwards the bound token on all requests, including image-path lookups and binary Commons fetches. Preserve its existing `X-Daedalus-Caller` header for the iteration-integrity guard. Capability checking is strict boolean validation.
- Claude retains repo-backed provider knowledge through a bounded private snapshot of tracked skill/reference text, at the existing relative paths, plus the same bounded bootstrap used by Codex. No broad repo read grant is added. Source and destination aliases/multiple hard links are rejected, and resume preserves previously copied files. Executable scripts and all untracked/user/global files are omitted.
- Verified the installed Claude/Codex primary CLI help without an authenticated or paid turn. Claude's restricted mode ignores user/project/local settings and confines file tools; strict MCP config admits only the explicit bridge. Add `--disable-slash-commands` to suppress automatic slash-command skills because trusted repo knowledge is supplied explicitly. These flag and mocked-launch checks do not establish native global instruction discovery behavior or paid MCP execution.
- Source ZIPs use the shipped tracked-text inventory if Git is unavailable; no recursive fallback admits untracked files. Run `python3 scripts/generate-provider-knowledge-manifest.py` when adding/removing provider knowledge files, after staging the new paths so the tracked inventory includes them.
- Peer review found a size-accounting race if a source grows between metadata inspection and open. Aggregate actual bounded bytes after reading, before retaining or writing them, and bound bootstrap reads to their prompt limit plus one character. Regression tests cover a growing source both over and exactly at the aggregate boundary.

Validation is limited to mocked subprocesses and temporary synthetic stores; no paid turn, real library operation, backend restart or account credential access is authorized by these tests.

The focused runner, profile, knowledge snapshot, workspace authority, dispatch and Commons-agent gate passed **162 tests**; including the main WebSocket integration/dispatch tests passed **172 tests**. Existing Claude/Codex/Daedalus cancellation tests remain part of this gate. New checks cover Krea discovery alongside private profiles, exact child identity, vault/API credential exclusion, daemon refusal before launch, strict capability validation, source ZIP fallback, immutable snapshot files and alias/size rejection. The Codex fake-CLI tests stub its default-model preference reader so they do not inspect the user's real Codex configuration. `git diff --check` passed.
