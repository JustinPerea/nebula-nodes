# Cinema art-direction backend decisions — 2026-10-07

- Scope is the existing Cinema Scene handler, including the existing single-shot execution path. Camera Rig becomes labeled prompt guidance. Reference Set priorities determine reference order/inclusion; their saved `*_weight`/`weight` keys stay compatible and do not become invented provider adherence fields.
- Character expansion runs first. Its frozen trait string and stored reference precedence remain intact. Camera guidance and the reference-role legend are appended afterward. An absent, empty, or all-zero Reference Set leaves the existing prompt and reference sequence unchanged, including duplicate legacy references.
- Active Reference Set items sort by priority descending, with stable ties. Zero excludes that role's items. Combined Character/shot/role URLs are delivered once in first-occurrence order, with all surviving roles labeled using the actual 1-based image indexes. A reference also used by Character keeps its original position. Utility producers use finite defaults for malformed/nonfinite numeric settings; malformed directly supplied typed camera values fail before a provider call.
- Limits follow the actual adapter and selected model: Flux Kontext uses one singular image; Seedream edit uses ten plural images; Nano Banana 2/Pro use fourteen; original Gemini 2.5 routes use a conservative Cinema limit of three based on Google's quality recommendation, not a claimed vendor hard cap. Unknown selectors fail clearly. Every final combined list is checked even without Character. Character's old standalone expansion API remains unchanged.
- Inspection uncovered an existing Seedream routing defect: Cinema references were sent to a text-to-image route that did not declare reference images. The adapter repair in the companion capability change now selects `/edit` when references are present. Cinema submits only the actual singular/plural reference input, avoiding fabricated duplicate input fields.
- Seedream receives its actual `image_size` field. Common aspect ratios use schema enums; other representable ratios use valid integer dimensions with a 4096px long side (2.39:1 becomes 4096×1714). An explicit valid `scene.base.params.image_size` is authoritative, preserving deliberate saved-recipe dimensions. Invalid sizes or unrepresentable ratios fail before submission. The source scene recipe is not rewritten by this translation.
- The module description now calls the per-shot hash an input hash rather than claiming an unimplemented per-shot cache. Graph caching and explicit single-shot reruns retain their existing ownership.
- Final review found that FAL's universal request builder applies model params after resolved ports. Cinema now rejects saved `scene.base.params.prompt`, `image_url`, and `image_urls` fields rather than allowing them to overwrite translated guidance/references after cap validation. Rejection occurs before transport and preserves the source recipe. The shared universal builder remains unchanged.
- Cinema uses its own adapter-limit check after Character expansion at scene preflight and per shot. This preserves the shared expansion API while making original Gemini 2.5's conservative limit accurate in UI errors too.
- The adapter default applies only when the base's `model` parameter is missing. Explicit `None`, an empty string, booleans, numbers or containers are rejected before transport. This avoids assigning the default's reference limit while a provider adapter actually dispatches an invalid explicit selector. Saved values are not normalized or rewritten.
