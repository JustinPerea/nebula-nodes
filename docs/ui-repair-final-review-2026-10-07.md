Post-write GET failure exposes a read-only refresh retry. App cache reads cannot restore outdated provider readiness. Browser keys are trimmed consistently with the input's blank-key message.
- Cinema reference completion patches the current node/shot by stable ID. Request identity, target deletion/retyping, removal, retry and graph replacement revoke old uploads. Pending/failed references gate the affected generation admission; cleanup and refresh do not submit generation.
- Cinema authoring persistence serializes per-node writes, coalesces later edits, reads current runtime at dispatch and protects unsettled authoring against earlier WebSocket echoes. Runtime media merges by stable shot ID while recognized old write echoes cannot rewind it. Deleted-shot ports and edges follow the authored shot set; immutable run records are separate.

Canonical prompts, uploads, settings, shot order, new shots and variation/selection history remain intact. A private marker proves produced output for successful, failed, cancelled and cached/context executions without accepting or serializing client runtime proof. Delayed executed events retain the whole recipe's artifacts for history while live ports merge only currently authored shot IDs.
- Import reservation suspends unsent/latest Cinema authoring and cancels old request ownership. Rejected import resumes only surviving targets with fresh runtime. Accepted import emits `graphReplaced: true`; the frontend revokes old uploads/persistence/suspension before adopting canonical nodes, edges, positions and blank outputs. This also covers same-ID replacement received through WebSocket when its HTTP acknowledgement is lost. Ordinary graph updates continue to merge frontend-only work.

## Review findings corrected

1. **A delayed authoring PUT could erase newer server runtime.** A pure synthetic CLIGraph reproduction changed a completed shot back to idle and removed variations while keeping its image output port. The Cinema-specific PUT merge now copies exact canonical `output`, `variations` and `selectedVariation` fields, including absence, onto incoming authored shots. New shot IDs start idle; import, generation and explicit promotion remain separate media authorities. Canonical route implementation was peer reviewed after this correction.
2. **Malformed legacy canonical shots blocked valid repair.** A stored `shots: null` or string could raise during lookup. It now acts as an empty canonical list; valid authoring repairs it without installing stale client media.
3. **Successful import with a lost HTTP acknowledgement could resume old authoring.** The explicit committed-import WebSocket signal now discards old suspension and uses full graph replacement semantics, including empty imports and removed frontend-only nodes.
4. **Settings feedback could contradict the committed state.** A post-save refresh failure no longer announces the submitted fields as unsaved. Whitespace-only browser keys are trimmed and preserve configured keys consistently with the explicit Remove action.
5. **Whole-scene completion could erase authoring accepted during its run.** Generic terminal parameter sync copied the recipe's old entire scene over newer prompts, references and shot order. Cinema now merges produced `output` only by surviving shot ID, preserving exact canonical variation/selection fields. Untouched copied outputs cannot masquerade as a completed shot; cache hits mark rebound output metadata explicitly and iterator contexts carry the marker through completion/cancellation. Canonical output ports filter removed IDs and preserve current siblings while the normalized event still carries earlier recipe artifacts. Partial cancellation also installs the actually settled shot's done/error port with its runtime, so downstream reuse after Stop agrees with the displayed scene result.
