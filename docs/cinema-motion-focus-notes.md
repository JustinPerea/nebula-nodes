# Cinema motion handoff: Canvas focus decisions

- `uiStore.requestCanvasNodeFocus(nodeId)` stores a volatile request ID, selects the real graph node, and returns to Canvas without resetting drafts, connections, history, or starting generation. The matching request ID alone may clear the request.
- A monotonic, volatile focus revision survives request consumption. Delayed automatic fits capture it and yield if a newer explicit handoff has occurred. App hydration also records whether a handoff was already pending at mount, so consumption cannot re-enable its scheduled all-nodes fit.
- Canvas waits for the requested node's internal measured width/height and initialized viewport. Other unmeasured nodes do not delay this handoff. A removed target releases the stale request.
- The target-only fit uses existing chrome-aware padding, a maximum zoom of 1, and a 300 ms transition (0 ms for reduced motion). Canvas mounts with its initial automatic fit disabled when a handoff already exists.
- Selection is reapplied when the measured handoff begins in case hydration/graphSync replaced the node selection while it waited. Selected edges are deselected without deleting their connections.
- Automatic fit timers are cancelled on Canvas unmount, while their listener no longer reinitializes on every node-count render. A new regression initially failed because that cleanup cancelled the ordinary node-added fit; reading the live node count instead preserves it.
- API contract checked against the installed `@xyflow/react` declarations/source and canonical [React Flow instance documentation](https://reactflow.dev/api-reference/types/react-flow-instance), [useInternalNode documentation](https://reactflow.dev/api-reference/hooks/use-internal-node), and [FitViewOptions documentation](https://reactflow.dev/api-reference/types/fit-view-options). No dependency changes.

Validation: six focused/adjacent frontend files passed 37 tests. The 19 new cases cover store request identity/selection/volatile storage, Canvas measurement/viewport readiness and target-only fitting, reduced motion, deleted targets, stale fit completions, delayed all-nodes timers, preserved ordinary node-added fit, and pre-mount/pending/settled App hydration handoffs. Targeted ESLint, TypeScript, and `git diff --check` passed. These are component/store tests with a mocked viewport API; integrated native browser proof belongs to the root acceptance pass. No paid generation or provider connection was used.
