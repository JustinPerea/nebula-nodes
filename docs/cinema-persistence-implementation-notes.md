# Cinema scene persistence decisions — 2026-10-07

- Scene edits now serialize per CLI-origin node and coalesce later edits while one PUT is in flight. Each dispatched request rereads current params/media; Inspector debounces join the same queue rather than overtaking Studio writes.
- The latest authored scene stays overlaid while persistence is unsettled. Scene authoring excludes shot output, variations and the selected variation; incoming media still merges by stable shot ID. A bounded list of 32 dispatched snapshots identifies stale write echoes so they cannot replace newer local media, ports follow the authored shot list, and removed-shot outputs stay removed.
- A matching latest WebSocket scene and settled HTTP write release the overlay. HTTP and WebSocket arrival order is allowed. If the socket is disconnected after an HTTP success, a five-second bound releases the overlay instead of hiding future external edits indefinitely. Failed final writes also release it; a later explicit edit retries persistence. No automatic generation occurs.
- `clearCinemaScenePersistence(nodeId?)` aborts owned client requests, cancels queued/debounced writes, and fences callbacks by queue identity. The root invokes it for graph lifetime replacement and deleted/retyped targets. A client abort cannot roll back a write already committed by the server; this frontend repair does not add a backend graph revision protocol.
- Reserving a graph import suspends Cinema authoring instead of discarding it. This removes old request/echo ownership before import WebSocket hydration. A rejected import restores the latest captured authoring onto a surviving same-ID Cinema target, merges its fresh runtime media by shot ID, and resumes only parameter persistence. An accepted `loadGraph`, explicit clear, target removal/retype or pending backend fresh-start discards the old suspension.
- A committed import emits `graphReplaced: true` on its WebSocket snapshot. Before hydration, the frontend discards old Cinema upload/persistence ownership and suspended authoring, then adopts the complete incoming graph, including canonical positions, empty outputs and edges. A lost HTTP acknowledgement therefore cannot resume an old same-ID draft when this commit notification was received. Ordinary graphSync remains a merge. If both acknowledgement channels are lost, there is still no general backend graph revision protocol.
- A delayed whole-scene `executed` event records every produced recipe output in immutable history, then merges only surviving current shot ports into the live node. Results for shots added after admission remain visible; deleted recipe shots cannot recreate live ports or clear a newer sibling result. The event does not replace current authored scene fields.
- Tests use delayed synthetic HTTP and WebSocket events. They do not access a provider or the user's running workspace.
