# Batch backend decisions — 2026-10-07

- Restored the archived branch's useful single-text authoring feature on the current invocation scheduler. The old `VariantSet` scheduler was not ported: it failed to retain per-item results for further downstream nodes, and its text-only substitution bypassed current port contracts.
- Batch has no inputs; its retained `set` handle emits an ordinary scalar `Text` per item. Existing `batch_outputs` retain earlier snapshots. Optional `variant` and parallel `batch_variants` carry labels and lineage beside those values; neither changes provider input contracts.
- `items_text` and `display_name` must be strings. `by_line` splits only newline characters, trims and omits blank lines; `none` preserves one nonempty raw item, including whitespace. CRLF works through trimming, while CR-only and Unicode separators stay inside one item, matching the visible source count. Unsupported split modes and caps outside integer 1–25 fail closed. Default cap is 10. Batch overflow is a static preflight error before any graph handler runs; ordinary iterators retain their existing truncation behavior.
- Line trimming explicitly uses ECMAScript's whitespace set instead of Python's default `strip()`: BOM is removed, while U+0085 and U+001C remain item text. The set follows [TrimString](https://tc39.es/ecma262/multipage/text-processing.html#sec-trimstring) and its [WhiteSpace and LineTerminator productions](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-white-space), checked against the installed JavaScript runtime over all Unicode code points. `none` still performs no trimming. Regression tests cover these differences and every supported trim character.
- Attribution matches the source card: a display name empty under the same JavaScript trim predicate displays `Batch`; nonblank names retain their original raw text. No saved source parameter is rewritten.
- Explicit Batch positions, including duplicate text, are separate creative variants. Their cache discriminator contains the full invocation context (source IDs and item indices). It is omitted entirely for non-Batch work so existing cache keys remain byte-for-byte compatible. Warm replay retains original per-item effective settings and artifact bytes.
- Lineage comes from the actual planned axis items and propagates through current scalar cascades and supported nested iterators. Labels are bounded to 40 characters, and output index is the stable per-node invocation ordinal. Independent axes still fail preflight instead of implicitly starting Cross/Pair work. World Labs operations retain their existing recovery-aware rejection inside batches.
- Handler progress/error events inherit a task-local variant scope. Execution run correlation and current cancellation fences are preserved. Failed/cancelled runs keep successful earlier files and manifest records through existing cleanup.
- Verification uses registered local utilities and PNG fixtures with mocked provider handlers; no paid generation or provider adherence claims are made.
- The authoritative local-execution inventory and utility manifest include Batch, with a manifest-driven red/blue scalar cascade fixture. Contract coverage asserts its real source ports and bounded defaults. The maintained browser smoke scenario includes that cascade and lineage expectations; it was syntax-checked here, not run through browser automation.

Final focused validation: 167 tests passed across Batch, iterator execution, cache, engine, node contracts, utility fixtures and video QC suites. This includes task-local progress serialization with run correlation, seven-color scalar cascades, duplicate-text cache replay, fixed-filename artifact separation, frozen-recipe replay, failure/cancellation settlement, strict preflight rejection, Unicode parser/name parity, nested lineage, and unchanged ordinary iterator behavior. Earlier cancellation, chat-upload event normalization and CLI/API integration checks also passed. The aggregate suite is verified separately by the coordinating agent.
