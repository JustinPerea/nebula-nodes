# Cinema shared settings layout decisions

- Scene settings use a native `details` disclosure, closed on entry. The collapsed summary reads current authored model, aspect, film look, palette color count and character reference count; opening or closing it does not write scene data or invoke generation.
- Optional palette/look summaries describe what is saved, rather than claiming the editor's draft defaults have already been applied. Known model and look IDs have readable labels; unknown saved model/aspect/method values remain visible so the selector cannot silently imply another choice.
- Scene and shot art controls share the same reusable palette and film look components. Scene callbacks remain functional updates against the latest spec, preserving parameters, sheets, unrelated controls, outputs and variations that changed between render and edit.
- Active character upload ownership, progress and recovery controls sit outside the disclosure. Users can retry or remove a failed upload while settings are closed. Character attachment, connected reference ownership and existing upload input behavior are retained inside settings.
- Native disclosure state is view state only and is not persisted into graph authoring. Expanded body sizing is handled by the root Cinema layout styles; no backend/provider or generation behavior changes are needed in this slice.
- Focused verification: eight shared-layout tests passed, covering native collapse/expand, actual and absent summaries, unknown saved selectors, visible closed upload recovery, multi-attachment/connected ownership, latest model/aspect/art edits and lean named-look selection. Assigned-file ESLint and whitespace checks passed. Native browser layout verification belongs to the parent integration pass; jsdom role queries expose native `details` descendants even while closed, so the tests assert actual element visibility as well as `open` state.
