# 2026-10-21 — `nebula nodes` lists what runs here, like find_nodes

Branch `fix/cli-nodes-what-runs-here` from origin/main 296e9199 (#148). Backend CLI, one route constant, docs; no frontend file changed.

- **Why.** In the Q104 measurement rerun (Justin's Q104 a; write-up in PR #150, "Rerun after #144"), run B3's CLI agent browsed `nebula nodes --category image-gen`. It listed all 78 image node types with no sign of which could run, so the agent picked FLUX.2 [pro] with no BFL or fal key set, `nebula propose` took it ("If the person accepts, the run fails"), and the agent then proposed Nano Banana and left the first proposal open. MCP's `find_nodes` already answered this correctly. Justin's standing rule: "Every feature we add needs to make sure we include MCP support for agents", and each MCP tool and its `nebula` twin give the same answer.
- **What changed.** `nebula nodes` (and its alias `nebula find`) now reads `GET /api/agent/nodes`, the route `find_nodes` reads, so ranking, readiness and prices come from one place. By default it lists only node types that run here, grouped by category, each with how it runs (key, free, krea, nous) and its list price at default settings (free, $0.13, $0.0047–0.43, no list price). Each category heading says "13 of 78 run here". The last line says how many were left out and gives the exact command: "65 more need a key: `nebula nodes --category image --all` lists them with what each needs." `--all` lists those too, each with the route's `missing` ("needs BFL_API_KEY or FAL_KEY in Settings > Providers"). `--json` prints the route's answer, which equals `find_nodes` for the same query, category, ready_only and limit. `--limit N` cuts the table and says "Showing N of M". Words, `--filter`, hidden `--query` and `--category` (id or short name) work as before.
- **No default limit in the CLI.** `find_nodes` defaults to 20 rows (100 at most) because an MCP tool result can't be piped. A terminal table is read whole or piped through `grep`/`head`, and a capped `--category image` would cut a category short without saying much. So the CLI asks for every match, and `--limit N` gives MCP's cut when wanted. To let `--all` get the whole catalog (308 node types today) in one call, the route's cap went from 100 to `AGENT_NODES_MAX` = 2,000 in main.py. MCP still clamps `limit` to 100 itself, so MCP answers are unchanged. A test pins the CLI's `ALL_NODES` to the route's cap and checks the cap is above the catalog size.
- **Words now match descriptions too.** The route has always matched the id, name or description; the old CLI matched only id and name. Using the route makes them agree. The CLI help and the `find_nodes` docstring said "id or name"; both now say "id, name or description" (the docstring was simply wrong). The MCP INSTRUCTIONS paragraph is untouched (it is at 2,994 of 3,000).
- **Order.** Rows keep the route's order inside a category (ready first, then exact id, id prefix, name hits, then by name). With words, categories come in the order of their best match, so the first row printed is the route's first. Without words, categories follow `node_categories.ORDER` (utility, moodboard, character, image, ...), the same order as `nebula context`.
- **`nebula context`.** Its CLI hint for a cut node list is now "`nebula nodes --category <category>` lists the rest with prices", and the text output adds one line under NODES THAT RUN HERE: "(249 more can't run here yet: `nebula nodes --all` lists them with what each needs)". That line is printed by the CLI formatter, not sent in the start JSON, so the start budgets don't change.
- **The person's path.** In a terminal with no keys, `nebula nodes` shows the free building blocks (preview, text input, moodboard, the local QC and cinema nodes) and the line pointing to `--all` for the full catalog. A search where nothing runs says so: "Nothing that matches 'upscale' runs here yet." then "12 need a key: `nebula nodes upscale --all` ...". "No nodes match ..." with the category list is kept for a search that matches nothing at all.
- **Decisions not in the spec.** The left-out line says "need a key", "need a key or a Krea sign-in", or "other setup", from the route's `missing` text (`node_readiness.KREA_SIGN_IN` for a sign-in). The free QC nodes print their `needsKeyFor` at the end of the row with `describe_node` changed to `` `nebula info <id>` ``. The table is one HTTP call (ready_only=false, every match), filtered locally; `--json` makes the exact call the person asked for, so it is always the route's own answer. The old `format_node_table` (id, name, apiProvider) is gone; its only caller was `nebula nodes`.
- **Docs.** skills/nebula/SKILL.md: the `nebula nodes` row says what it shows, `--all` and `--json`, and a line says to build only with nodes it lists without `--all`. docs/MCP-SETUP.md: the find_nodes bullet names its CLI twin and the limit choice, the start-here table's `nodes` row has the CLI hint and the new context line, the route paragraph has the new cap, and the nebula skill section says what `nebula nodes` shows (with the B3 reason). Four provider docs (Nano Banana, Meshy, Hunyuan3D, GPT Image 2) said "Run `nebula nodes` to confirm node IDs", which now shows only what runs; they now give a search word and mention `--all`. `scripts/count_agent_turns.py` still classes `nodes` as lookup; no change needed. The 2026-10-20 headless run write-up is a record and stays as it was.
