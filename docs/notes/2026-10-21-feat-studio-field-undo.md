# 2026-10-21 — Board fields are undo steps in Moodboard Studio

Branch `feat/studio-field-undo` from origin/main a330dc64 (after #127). Justin's answer to Q83: "a) Yes, now: a small PR right after #127. A field becomes one step when you leave it, and Cmd+Z inside a text box still undoes your typing first."

- **What changed.** Every board field the Studio edits is now a step in the same undo queue #127 built: the name, the board's notes, mode, strength, Direction, Avoid, the pinned colours, the clash mode, the colour choices (Keep anyway, Leave out, Reset), Send notes and the hand-written brief. A text field's step closes when it loses focus, however many 600 ms saves went out while it was typed. A control's step closes when its change is done: the strength slider when let go (arrow keys: when the slider loses focus or Cmd+Z is pressed), a colour or Avoid item added or removed, the mode, a switch, a clash mode or a colour choice. Leaving a field as it was (or typing and deleting back) adds no step. The toast names the field ("Undid: Direction").
- **The undo comes from the server.** `PUT /api/moodboards/{id}` now answers with the board plus `undo`, the `restore` built from the same diff it already journals (`{ops: []}` when nothing changed). The Studio sends one PUT per field step, so each answer's `undo` is exactly that step's; a step that saved twice keeps both, the later first, as #127 does for a card step's batches. Undo and redo go through `POST /edits` like every other step: no client-side guess of the old value anywhere.
- **Stale steps follow #127's rule.** A field changed since (an agent, another window, an accepted proposal) is left as it is and the toast says so ("Direction changed since, left as is"); an undo that put nothing back leaves nothing to redo. This is the server's own `restore` check, the same one card steps and the CLI/MCP undo use.
- **Cmd+Z in text boxes.** `isStudioShortcutTarget` now takes the key: undo and redo yield only to text boxes (text-type inputs, textareas, contenteditable) and dialogs. Before, they also yielded on sliders, checkboxes and the mode select, so after dragging the strength slider (focus stays on it) Cmd+Z did nothing. Delete and Cmd+S keep the old rule.
- **Image notes (decision not in the spec).** #127 made a note one step until it was sent (600 ms). Justin's rule is "a field becomes one step when you leave it", so a note on an image is now one step until its box loses focus too (`open` steps in `lib/boardUndo.ts`, sealed on blur). The weight slider on an image keeps #127's rule.
- **Agent support.** Agents could already take back their own field edits: `moodboard_update` / `nebula moodboard set --json` return `previous.undo`, a checked `restore`. Its fields slice used to be computed in the client (`moodboard_client` called `fields_slice` on the board it read); it now takes the `undo` the PUT answered with and falls back to computing it on an older Nebula. A raw HTTP caller gets the same `undo` from the PUT. Docs: docs/MCP-SETUP.md and skills/nebula/SKILL.md say so, and that the person's Cmd+Z never takes back an agent's edit (Q62's Agent log Undo is separate). No MCP tool or CLI flag was needed: the existing `moodboard_update(**previous)` and `set --restore` cover it.
- **Tradeoffs.** One PUT per field step means two fields changed inside one 600 ms window go as two PUTs (two versions) instead of one. The analysis-clear (`analysis: null`) rides with the first PUT. An earlier field step whose change was never sent and whose field a newer step then takes over is merged into the newer one (the draft holds one value, sent once); one whose PUT is already out stays its own step. Keep (the brief override's "Keep" button) is its own route and stays out of the queue.
- **Surprises.** In the live check, two taps of the arrow key on the strength slider made two steps (it closed on keyup), so Cmd+Z only went back one tap; the slider now closes its step on pointer-up or blur, and Cmd+Z closes any open step first. The machine's load (44) made the page's 650 ms backend probe miss a backend started at background priority under `lg`; it was run with `--gate`.

- **Review.** Three confirmed findings, each pinned by a test seen failing first, then fixed. (1) An open image note whose later save changed nothing (typed '!' then Backspace) lost its whole step, undo and all, so Cmd+Z skipped to the step before; the save loop now forgets a step after an empty `undo` only if it never landed (`MoodboardStudioView` persist). (2) A field changed when nothing can save (a blank name, a board with no images) left a pending step on top that blocked every Cmd+Z; since none of it reached the server, Cmd+Z now puts that field back in the draft (the tracker keeps each step's start values, `unsentStart`, only while no PUT went out for it), names it in the toast, and the next Cmd+Z reaches the step under it. Mode, strength and notes clear the analysis when they change, so this local undo keeps the server's analysis when nothing steering is left unsent (else the next save would have sent `analysis: null`; an extra test caught it). (3) A field changed and put back before leaving cleared the redo stack; a new step now keeps the redo stack it cleared (`clearedRedo`), gives it back if it is forgotten while still the newest step with nothing undone since, and drops it once it lands. Applied to card steps as well as field steps, since a note typed and put back clears redo the same way.
