# 2026-10-21 — model_catalog / model_schema read a model's ports from universal_ports

Branch `fix/mcp-catalogs-universal-ports`, from origin/main `55bfee41` (after #128 and #132). No paid provider call; no package installed; no frontend file changed.

- **What changed and why.** #128 (`model_catalog`, `model_schema`) and #132 (`services/universal_ports.py`) both named this follow-up: #132's notes say "`model_schema`/`model_catalog` ... should call `services.universal_ports` (or the route) so the two can't disagree", and #128's MCP-SETUP section called moving ports into the backend "open work". Now:
  - `model_schema(provider, model_id)` returns `ports: {inputs, outputs}` for OpenRouter, Nous Portal and Replicate, each port as the canvas draws it (`id`, `label`, `dataType`, `required`, `multiple`). They are `universal_ports.configure(...)`'s ports for that model, from the same catalog row or Replicate schema the edit reads (the same routes and cache), so what the agent reads is what `edit_canvas` configures, `look_at_canvas` shows and the canvas draws.
  - Replicate: `params` (the model's other inputs, the Inspector's controls from `universal_ports.replicate_inputs`) replaces #128's `inputs` list with its `port: true/false` flags, and #128's `output {port, note}` is gone (the output is in `ports.outputs`). `versionId`, `description`, `inputSchema`, `outputSchema` stay.
  - `model_catalog` rows for OpenRouter and Nous carry `ports: {inputs, outputs}` as port ids (the shape `look_at_canvas` and an edit's `modelPorts` use). Quiver rows don't: the Quiver nodes' ports are fixed.
  - Removed from `mcp_server.py`: `_replicate_inputs`, `_replicate_output`, `_REPLICATE_OUTPUT_NOTE`, `_REPLICATE_MODEL` (it uses `universal_ports.REPLICATE_MODEL`). No port rule is left in the MCP server; a test pins that.
  - `edit_canvas`: #132 already configures the node before checking wires, so setting a model and wiring its `images` input, `image` output or a Replicate file input in the same edit was accepted already; confirmed with new tests (OpenRouter vision + image-output on one node, Replicate with two file inputs, Nous image output). No `main.py` change.
  - Docs: docs/MCP-SETUP.md (the tool list entry, the "Universal nodes over MCP" section rewritten without the stale "edit_canvas refuses `images`" and "open work" lines, one line in "Universal nodes: ports from the model"), skills/nebula/SKILL.md (a paragraph on reading a model's ports before an apply), both tool docstrings.
- **Decisions not in the brief.**
  - The MCP server imports `services.universal_ports` and applies it to the data it already fetched through the routes, rather than calling `POST /api/universal/ports`. Same function, same data (the routes `look_up` calls), one request instead of two, and the raw Replicate schema still comes back. It already imports other `services` modules, so this adds no new dependency.
  - The catalog rows use port ids only (types are on `model_schema`), to keep a 100-row answer short.
  - `model_schema`'s output shape changed for Replicate (`inputs`/`output` → `ports`/`params`). Agents read it fresh each session; nothing else in the repo read the old keys (checked: backend, CLI, frontend, skills, docs).
- **Tradeoffs.** Replicate `params` entries carry the description cut to 80 characters (the Inspector's placeholder) where #128 gave 200; the full text is in `inputSchema`.
- **Surprise (open, needs Justin's call).** A Replicate model that returns a video or audio file has an output schema of a plain `uri` string, the same as an image model, so `universal_ports` (as the picker did before it) gives it an `image` output. Its run names the output `video` or `audio` by the file's extension (`handlers/replicate_universal._infer_output_type`), and the engine passes outputs by handle name, so a wire from `image` gets nothing on those runs. Before #132 an agent could wire `video` (any handle was accepted on Replicate); now the node declares only `image`, so the wire is refused. #128's `output.note` told agents to wire `video`/`audio`, which would now be refused, so it went with the duplicate logic. The fix needs a decision (type Replicate file outputs from the model's metadata, add `video`/`audio` ports, or have the run fill the declared port), so it isn't built here.
