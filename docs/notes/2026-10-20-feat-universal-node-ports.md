# 2026-10-20 — Universal-node ports on the backend (OpenRouter, Nous Portal, Replicate)

Branch `feat/universal-node-ports` (from `23f11b8e`), uncommitted. Brief: batch-2 small-tools review finding (agents couldn't build an OpenRouter vision or image-output node; Replicate wires drew no port).

- **One source.** `backend/services/universal_ports.py` works out a universal node's ports from its model: OpenRouter/Nous from the cached model list row (`architecture.input_modalities`/`output_modalities`), Replicate from the cached OpenAPI schema. Rules are ports of the old TS picker (`configureOpenRouterModel`, `fetchReplicateSchemaAndConfigure`), pinned by `contracts/fixtures/universal-ports/picker-cases.json`, whose `expected` was captured from the verbatim old TS (`frontend/tests/universalPorts.pickerParity.test.ts`) and replayed by the Python tests.
- **Ports are stored, stamped with the model.** `_model_ports = {model, inputs, outputs}` is a canvas-owned (`_`) param, so ports don't depend on a 5-minute cache, and a saved node without the stamp (every graph saved before this) keeps exactly the ports it has today. A stamp whose model differs from the current model is ignored (the definition's ports apply). `port_contracts.node_ports` reads it (cinema first, then the stamp, then the definition) and is used by `_declared_port`, `_cli_node_to_rf`, import validation, export and node-and-connect edge typing.
- **Agents.** `edit_canvas`/`nebula apply`, proposals (create and accept) and the node routes, for anyone but the person, reconfigure a node whenever its `model`/`model_id` changes; there is no configure tool. Models are looked up before the mutation lock. Agents still can't write `_` params (422). Refusals instead of silent drops: a wire on a port the new model lacks ("…Unwire them in the same edit (`unwire`)…"), and a wire to an unknown port when the model can't be read, with the reason (no OPENROUTER_API_KEY / REPLICATE_API_TOKEN, Nous signed out, unknown model, HTTP status). The apply result adds `modelPorts`/`modelPortNotes`; `look_at_canvas` nodes carry `ports`; `describe_node` has `modelPorts`; the CLI prints "Ports of n3 (model): in …; out …".
- **The person's picker** (person only: `require_person`, since it drops wires past the approved-run and billing checks an edit gets; anyone else edits or PUTs, which refuse instead; tightened by the coordinator after the commit security review) calls `POST /api/graph/node/{id}/model` (or `POST /api/universal/ports` for a node the backend doesn't hold yet), which configures, prunes wires that don't fit, commits, broadcasts and journals. The frontend no longer works out ports itself.
