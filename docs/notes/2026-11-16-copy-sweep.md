# Copy sweep: one wording for names, Settings, missing keys and Try again (2026-11-16)

Branch copy/sweep-2026-11, from main 2cb8183d. The pull request changes wording, plus the two small pieces of behaviour the wording needed (the missing-key kind on the wire, and which Cinema upload failures offer Try again). It touches no high-tier file. The high-tier wording (spend refusals, four handlers' own missing-key lines, the Ideogram Character port label) is a separate pull request.

## Rules the strings now follow

- **Names:** the six studio card and node names are in sentence case ("Remotion composition", "Cinema scene", "Camera rig", "Reference set", "Paper source", "Video edit"). A port or setting with no written label gets one in sentence case from its key, split into words (`services/setting_labels.py`). Port and setting labels written by hand in the node definitions are not changed here.
- **Missing keys:** "Add an OpenAI API key in Settings to run this node." A set-up failure reads "Nebula couldn’t set up “X” because it needs an OpenAI API key. Add one in Settings." The badge reads "Needs an OpenAI API key". Hugging Face and Replicate keep "token".
- **Failures beside a Try again button** end in "Try again." and take the form "Nebula couldn’t ‹do the thing› because ‹reason›. Try again." A failure that trying again cannot fix names the fix and has no Try again.
- **Moodboard:** the thing is a "moodboard" in every sentence; "Board" stays only as the name of the Studio's canvas view. Inside a sentence "#3" is "image 3"; badges, chips and buttons keep "#3".
- **Personal agents** are "Your Claude", "Your Codex", "Your Gemini" and "Your Antigravity" at the start of a line and "your Claude" inside a sentence (`personal_agents.in_sentence`, `agentNameInSentence`). A name saved under an older form is shown as saved.
- **Apostrophes and quotes** in the sentences this sweep touched are curly.

## Behaviour that changed with the wording

- **A missing key draws neutral, and only a missing key does.** The backend marks the error where it is made: `ValidationErrorDetail.missing_key` for a pre-call check (set by `.keyed()`), `ErrorEvent.missing_credential` for a handler. `node_errors` stores the kind with the node's error, so a reload and a project switch draw it the same. The card reads `errorMissingKey`. A node draws neutral only when every one of its checks is a missing key; a second failing check on the same node is a failure. Four node kinds also read the card's own key state until the follow-up pull request (Known limits).
- **Agents' JSON:** each error in the WebSocket `validationError` event gains `missingKey`, and the canvas's REST validation answer gains `missingKey` when it is true. A refused run's `message`, `look_at_canvas`, `nebula look` and the journal are unchanged.
- **Cinema upload row:** a 400, 415 or 422 reads "because the server couldn’t read it as an image. Choose another image." with no Try again. Any other refusal reads "because the server didn’t accept it." with no Try again. Every other status reads as errorCopy’s clauses say it for a line beside a button (`actionFailedLine`): no answer "the server isn’t answering. Try again.", a 408 or a gateway's 502 to 504 "the server didn’t respond. Try again.", another 5xx "the server hit an error. Try again.", a 429 "the server is busy. Try again.", a 401 or 403 "you don’t have access to this anymore. Reload to sign in again." with no Try again. The row keeps no clauses of its own for those.

## Known limits

- Of the four handlers that the card’s key state still stands in for, three already raise `MissingCredentialError` for a missing key and only keep the older wording: `worldlabs.py` (WORLDLABS_API_KEY, the run and the export paths), `style_reference.py` (GOOGLE_API_KEY for Auto mode) and `veo.py` (GOOGLE_VERTEX_CREDENTIALS, and the retired-previews stop). `speridlabs_idol.py` has no missing-key stop of its own: HF_TOKEN is optional there, the handler runs without it, and its errors are `IdolSpaceError` and `ValueError`, none about a missing key. A plain error that is a missing key is therefore not raised by any of the four. Until the follow-up pull request, the nodes `worldlabs-environment`, `style-reference`, `speridlabs-idol` and `veo-3` still draw a run error neutral from the card’s own key state (`keyStatus === 'missing'`), in addition to the `errorMissingKey` rule (`PLAIN_MISSING_KEY_STOP_NODES` in `frontend/src/lib/missingKeyTone.ts`, used by the canvas cards, the Create Studio result card and the Batch node). That also draws another failing check on such a node neutral. `worldlabs-world-export` and `veo-3-flf` share those handler files and are not in the constant. Every other node kind reads only `errorMissingKey`.
- A node saved on a canvas with exactly the Title Case default of its own definition ("Remotion Composition") shows the new default ("Remotion composition") when the canvas loads, on the canvas (`withCurrentDefaultLabels` in `graphStore.loadGraph` and `loadProjectGraph`) and in the backend's read of a saved graph (`CLIGraph.load`). The saved file is not rewritten by the load; the next ordinary save stores the new label. A label the person changed stays, and so does another definition's former default.
- A personal agent's name saved under an older form is not migrated.
- `npm run check:ratchets` could run only its frontend half on the build machine; CI runs both.
