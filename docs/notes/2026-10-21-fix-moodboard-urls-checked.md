# 2026-10-21 — Board images must be Nebula's own files

Branch `fix/moodboard-urls-checked` from origin/main 6f9489dc. Follow-up to #133 (`fix/asset-urls-checked`), Q98. Justin's answer: "a) Yes: the same check, and the same placeholder for old boards (a follow-up PR)."

- **What changed and why.** #133 stopped a Style or Character from storing an image link to another site, because the app would fetch it and tell that host the person's address and when they looked. Boards had the same hole: any board write could store `https://...` and every place a board image is drawn would load it. Now every board write runs #133's check, and an old board that already holds such a link shows #133's placeholder instead of loading it.
- **Write paths.** `moodboard_store._normalize_images` is the single path for create, PUT and the edits `add` op, so the check sits there (`board_image_problem` in `services/stored_image_refs.py`, same `problem()` as #133, no shipped Style thumbnails). The edits `add` op checks first so the refusal names the op's own field ("ops[0] (add): urls[0] is an image link from outside Nebula ..."). The `restore` op inserts records directly; it now skips a slice whose image isn't Nebula's own and the board doesn't hold. `analysis` written through PUT or create is checked for outside links too (its urls reach generators as a style reference). The refusal reuses #133's shape with a board answer, `BOARD_ALLOWED`, that names the upload route and the tools that upload for you.
- **Old boards.** A url the board already holds is not checked again (#133's rule), so Studio can still save an old board without first removing a link the person may never have seen. The API read adds a computed `outsideImages` (ids, only when non-empty, never saved). The app draws the placeholder ("Image link from outside Nebula", `lib/storedImage.ts` + `OutsideImageNote`) on the canvas node, the Studio List view (cover, rail, tile), the Board view (card, selected side panel), the bundle preview, the Assets panel board rows and Recently deleted.
- **Runs and analysis.** An outside image is decided, not fetched: analysis gives it `status: "outside"`, an empty palette and a warning ("#N is an image link from outside Nebula, so it wasn't analyzed and no generator gets it. Replace it with an upload in Moodboard Studio."); `resolve_moodboard_image_path` returns None for it; the run bundle and `generator_analysis` leave it out and the run note says how many were left out. A board whose images are all outside still runs (with no images), matching #133's "decided" handling.
- **Agents.** MCP `moodboard_create`/`moodboard_add` already downloaded and uploaded a link; `nebula moodboard new/add <http url>` does too (the CLI process fetches it; the backend never does) and now refuses `data:`, `blob:` and `javascript:` clearly instead of "no such file". `moodboard_get` and `nebula moodboard show` mark outside images (`outside: true`, `outsideNote`, "[Image link from outside Nebula (not loaded)]"). Docstrings for moodboard_create/add/get/edit, docs/MCP-SETUP.md, skills/nebula/SKILL.md and contract 07 §1.19 say board images must be Nebula's own.
- **Commons import.** `import_moodboards` no longer fetches a board's remote links; it skips them with a reason. A loopback `/api/outputs` url is still read as a local output.
- **Decisions.** The strict `problem()` check, so a missing local file is refused too, as in #133. A restore slice for an image is skipped, not refused, so the rest of an undo still applies. Trash restore and moves are not re-checked (the board as stored is held). Analysis links are checked for outside links only (an analysis names the board's own images; local paths are checked on run).
- **Tradeoffs.** Undo can't bring back an old outside image once removed. Commons import loses remote-link boards' images (they show up as skips) instead of fetching them; that is the point of the rule, but it is a behaviour change.
- **Surprises.** The golden fixture had outside links on purpose (fake CDN urls); it now uses stored files, with the change documented in the golden test's docstring and its normalisation extended so the hash stays comparable. Many asset tests used fake https urls for board images and now use `stored_image_urls()`.
- **Security lens.** `is_outside_link` reads a link the way a browser does: protocol-relative `//host`, `/\host`, `http:/host`, `https:\\\\host`, tabs or newlines inside the scheme, `http://host\@127.0.0.1/`, `data:`, `blob:`, `file:`, `javascript:`, mixed case, a LAN host, an outside host with an `/api/outputs` path, a loopback url outside `/api/outputs`, a missing file, plain and encoded traversal are all refused (tests in `backend/tests/test_moodboard_image_refs.py`).
