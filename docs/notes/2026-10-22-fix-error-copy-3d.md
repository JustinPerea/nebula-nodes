# 2026-10-22 — A provider's answer gets GM's line, and no ids or parentheses reach the card (error copy round 3d)

Branch `fix/error-copy-3d`, from main `6b362b85` (#170, round 3c). No package installed, no paid provider call, no real key used.

## What changed and why

- **One status table, applied in one place.** GM's lines for a provider's answer: 401/403 "{Provider} didn't accept your API key. Check it in Settings, then run the node again.", 402 or an exhausted quota "Your {Provider} account is out of credits. Add credits, then run the node again.", 429 "{Provider} is busy. Wait a moment, then run the node again.", 5xx "{Provider} is having trouble right now. Try again in a few minutes.", and an empty or unreadable answer "{Provider} didn't return a result. Run the node again." The table lives in `execution/person_line.py` (`STATUS_LINES`, `status_line`); `execution/provider_status.py` `card_line()` applies it. The engine calls `card_line` at both of its ErrorEvent sites, and the Cinema scene calls it for a failed shot, so no handler was edited for the table. `card_line` knows the node, its params and the keys, so it names the provider the run actually called: the provider the text names at its start ("Meshy submit failed …"), else the route `services/node_route.select_route` took (a provider switcher's choice, or Auto's), named the way Settings names the key. A handler's own line always wins. A failure whose status or provider Nebula can't tell keeps today's line.
- **GM: "Raw provider text stays behind Details in every case."** A line written for a provider's answer rides with an additive `provider_text` on ErrorEvent (`providerText` on the wire, `errorProviderText` in node data, on a shot's `output`, and in `services/node_errors.py` so a reload keeps it). The card (`lib/nodeErrorCopy.ts`) then keeps the raw text behind a closed Details; a line in Nebula's own words still shows none. `with_provider_line()` marks a handler's line wrapped around a provider's words (Krea's refused node-app input, ElevenLabs' voice list, TypeSafe's damaged image).
- **Paid jobs Nebula stopped waiting on** say GM's "{Provider} is taking longer than usual. The job may still finish there and be billed, so check {Provider} before you run the node again." That is every poll limit on a job a paid provider accepted: the shared poll runner (`AsyncPollConfig.provider`, set by Runway and both Replicate handlers), Krea (gateway, account, MCP), MiniMax (both), fal.ai, xAI, Higgsfield, Gemini Omni, Veo (Gemini and Vertex), ElevenLabs Dubbing, Meshy, Ideogram training, and BFL, OpenRouter and BytePlus, whose 3c lines this replaces. A local or free wait keeps the classifier's line.
- **Empty answers** go through the table's `no_result` kind ("returned no", "did not return", "without returning", "returned non-JSON", …), named by the provider the text or route gives, not per-site strings.
- **File not found**: `missing_file_line(what, value)` now always says "A connected {image|audio|video} file can't be found. Connect it again, then run the node again.", taking the kind from the input's own words or the file's extension. - **Missing keys**: Veo's "previews retired" check (Vertex credentials), a multi-route node whose chosen route lacks its key, style reference and Jev mode now say GM's key line.
- **Krea**: GM's ten lines verbatim, with the Settings label "Krea · usage key" (pinned against `providerCatalog.ts`) and the node app's tool named in words.
- **No ids, no parameter keys, no parentheses** (3c-2's open items): 88 person lines the stronger guard refused now read GM's way, through `with_person_line` with the exception text unchanged. Model ids became names (`model_name`, the node's own Model option or the provider's spelling: "Seedance 2.5 on BytePlus", "Hailuo 2.3", "GPT-6 Astra"), values went into their own sentence (`it_was`: "Set Duration to whole seconds from 4 to 30. It was 3.5."), and field names come from the node's labels (`field_label`, `option_label`, `option_labels`), so Ideogram's "Ideogram num_images" reads "Images".
- **The guard learned** kebab-case ids with a digit, dated ids, the makers' id prefixes and parentheses (`FORBIDDEN_IN_A_LINE`), with field labels that carry a parenthesis ("Duration (ms)") allowed; and a `{model}` placeholder must be a name or label.

## Decisions not in the spec

- The key line uses each key's own word from `person_line.KEY_NAMES` ("API token" for Replicate and Krea, "credentials" for Vertex), not GM's literal "API key".
- Who answered: the provider the text names first wins over the route, so a FLUX 3 Video run whose fal.ai client says "fal.ai …" names fal.ai even if the route table changed meanwhile. httpx's own `HTTPStatusError` names no provider: every `raise_for_status()` is a download of a result or an input URL, not the provider's API.
- On the signed-in Krea plan a rejected key keeps today's line: there is no key to check.
- Quota words beat the status: OpenAI answers an exhausted quota with a 429 `insufficient_quota`, which reads as credits, not busy. BytePlus says an unpaid balance with an `…Overdue` code and no 402; it reads as credits too.
- MiniMax H3's PLAN_HINT goes behind Details with the provider's text. MiniMax V1's `base_resp` codes read as credits or a key only where the classifier's words catch them.
- A paid-job timeout line shows no Details (Nebula's own words).
- Line 10's form: "The node app didn't accept …" for a node app; for a desktop tool, {tool} is the tool's title or its name with `_`/`-` as spaces.
- Field-chosen files (the Image Input's File, style reference's Reference Image, Cinema Color's Palette Source) keep their own "The node's … can't be found. Choose it again …" lines: they aren't connected, so "Connect it again" would be wrong. Only connected inputs take GM's line.
- "Missing API key: X" is pre-run validation (lane 3e). A route its params block keeps its pre-run words.
- World Labs lines were left alone (3c's, pinned by `test_error_copy_round3c.py`).
- `person_line._param` reads `services.node_registry` directly, not `execution.maker_routes`: every module that raises a person line imports `person_line`, and `test_node_readiness.py` walks those imports for network calls.
- The note's H1 carries the file's date, 2026-10-22, like the other notes in this folder.

## Part 2 (3d-2): the status comes from the call

### What changed and why

- **Why.** 3d's table found the status by searching the error text, provider bodies included (`_STATUS_SHAPES`), which brought back the bug 3c fixed: reading facts out of free text. A presigned storage upload's 403 ("Runway upload failed (403): <Error>AccessDenied…", Krea Files' "upload failed (403)") read "Runway didn't accept your API key", though the key had just issued the upload ticket; "Prompt is too long: 500 characters over" read "{Provider} is having trouble right now"; and the job-failure fix was another text pattern (`_JOB_FAILED`) that a new provider's wording would slip past.
- **The status is attached where the provider's API answered.** `person_line.with_api_status(exc, status)` puts the HTTP status on the exception at the raise; `provider_status.http_status()` reads it, then a typed provider error's own `status_code`/`status` (BFLError, BytePlusError, QuiverError, TypeSafeError), and never the text. 90 exception constructions in 33 files now attach it (every "{Provider} {action} failed ({status}): {body}", "… API error {status}: …", the OpenRouter and Replicate `_error` builders, World Labs' `_raise_api_error`, the shared poll runner's submit and poll, the three stream runners' refusals, the Vertex token exchange, vision and prompt-enhance calls). - **Left on today's line, with a `# no API status:` comment saying why (8 raises).** Not the provider's API with the person's key: Runway's presigned storage upload (`Runway upload failed`), Krea Files' upload and its commit URL (both sent without the key), and downloads of results: Black Forest Labs' result from its signed URL, Replicate's result file, OpenRouter's finished video, ElevenLabs' dubbed audio, and Antigravity's download. httpx's own `HTTPStatusError` (every `raise_for_status()`, all downloads) still names no provider.

### Decisions not in the spec

- `with_api_status` uses its own attribute (`nebula_api_status`), not `status_code`, so no other code that reads `status_code` off an exception (poll_retry's 5xx retry, FastAPI handlers) changes behaviour.
- fal.ai's queue "result fetch" (JSON from fal's API with the key), MiniMax's `files/retrieve` (returns the download URL) and Gemini's Files API poll attach their status: they are the provider's API with the person's key, not a download of the bytes.
- "Returned non-JSON ({status})" raises attach their 2xx status; it selects no line, and the no-result line still applies.
- The fal.ai stream whose recovery poll reads FAILED is a job failure now, so its card says GM's general line with fal.ai's error behind Details instead of 3d's "fal.ai didn't return a result. Run the node again.", the same as fal.ai's queue path ("FAL job failed: …").
- Two wrappers still choose agents' hint by the cause's text ("404" in maker_routes' Gemini 2.5 check, "submit failed (401|402|403)" in the Meshy entitlement hint). They decide what agents read, not the card, and changing them would change agents' text in edge cases; they now carry the cause's status, and stay as they are (open item).
- The Replicate "no version" line names the field as "Model ID" in words (the function has no node to read the label from; the same file already says "the node's Model ID field").
- `test_error_copy_round3c2._raises` peels the new markers (`with_api_status`, `as_job_failure`, `with_call_facts`) so every guard still reads the exception inside them; the unlined baseline for `execution/stream_runner.py` went from 6 to 5 (the image stream's failure is built before its raise so it can take the slow-job line).

### Tradeoffs

- The guard reads a status in a raise's text by its expression (`….status_code`, or a name assigned from one, or a literal "error 401"-style shape). A status written through a helper it can't see (a message built in a variable first) needs its own test; the site tests cover Meshy, the poll runner, the chat stream, Krea, World Labs, OpenRouter, Replicate, ElevenLabs and Quiver.
- Words still read as busy and credits without a status (OpenAI's 429 `insufficient_quota`, BytePlus's `…Overdue`, "rate limit exceeded"): they are words, not a status in text.

### Surprises

- The guard found 98 constructions that write a status into their text, not the spec's ~68: the "API error {status}" family (OpenAI, Gemini, ElevenLabs, Ideogram, OpenRouter) and the error builders that return an exception (OpenRouter, Replicate, World Labs) count too.
- Four wrappers rebuild an exception from `str(exc)` and would have dropped the status the cause carried; the text search used to hide that.
- In the tests, monkeypatching `httpx.AsyncClient` twice chained the second mock to the first (the module attribute is global); the helper keeps the real class.

- `handlers/runway.py` (a presigned storage upload's 403): “Runway didn't accept your API key. Check it in Settings, then run the node again.” -> today's line, GM's general “That didn't work. Try again, or reload if it keeps happening.”, the raw text behind Details.
- `handlers/krea_workspace.py` (Krea Files' storage upload or commit, 403): “Krea didn't accept your API token. …” -> GM's general line.
- Any text with a number after a colon or in parentheses that isn't an attached status ("Prompt is too long: 500 characters over"): “{Provider} is having trouble right now. …” (or the key, credits or busy line) -> GM's general line or the classifier's.
- A provider message with an auth word but no 401/403 from the API: “{Provider} didn't accept your API key. …” -> today's line.
- A job the provider ran and reported failed with an auth word in its error ("unauthorized to fetch input"): the classifier's “The API key was rejected. Check your key for this provider in Settings.” -> GM's general line. (Agents' `category` for it: `auth` -> `unknown`.)
