- **C. "Antigravity (your setup)".** New `backend/services/antigravity_agent.py` (module docstring has the full reasoning).   - *Sign-in.* The server keeps its own Keychain login (service `gemini`, account `antigravity-acp`), separate from `agy`'s (`antigravity`), so `agy`'s login does not carry over. Settings runs Google's own ACP `authenticate oauth-personal` only on the person's click; the server opens the browser itself and Nebula surfaces the accounts.google.com link while it waits. Nebula stores only `signedIn: true`. Every chat start re-authenticates with `BROWSER=/usr/bin/true %s`, so a chat never pops a browser; a lost login says "Sign in again in Settings". Sign out calls ACP `logout`. Judgment call: this is the one place Nebula runs an agent's login flow, because there is no terminal command that signs this server in.
