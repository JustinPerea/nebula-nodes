# 2026-10-24 — Input cards name their file; the palette extract says why it found nothing

Branch `fix/drop-followups`, from `fix/canvas-drop-files` at ff9c60a4 (#188, about to merge).

- **What GM - Design asked for.** Two follow-ups to #188. (1) Audio Input and Document Input cards should show the file's name "in the same place and style as Image Input", cut in the middle when long so the extension stays: "quarterly-rep….pdf". (2) The palette's "Extract from reference" should report a failed upload in the canvas notice, as the file control does. When no colours come out it should say "Couldn't find colors in “{filename}”." with a reason line underneath: "Nebula can't read this image. Try a PNG or JPEG." or "The image is fully transparent." GM: "If the two cases can't be told apart, use only the heading. Don't guess the reason."
- **Surprise: Image Input has no file name on its card, and the name was never stored.** The Image Input card shows the picture and nothing else. No element or class draws a file name on any input card, so there was no "same place and style" to reuse. Worse, `/api/uploads` stores every file under its content hash (`3fa9…e1.pdf`), so `params.filePath`'s basename is a hash. The name the person gave the file was dropped everywhere: drop, Inspector and MCP `upload_file`. The Inspector's file button was showing that hash too.
- **The name is now kept, paired with the file it names.** A node that `/api/uploads` creates (canvas drop, `nebula upload`, MCP `upload_file`, any type) gets `_fileName: {file: <basename of filePath>, name: <name it was sent with>}`. The Inspector's file control writes the same param for `filePath`. The pair means a later filePath change (an agent's `edit_canvas`, a script) never leaves the old name on the card: the name shows only while `file` matches the current filePath's basename. Only the last part of a sent name is kept (`C:\me\a.pdf` and `../a.pdf` both become `a.pdf`). Readers: `frontend/src/lib/fileName.ts` (`inputFileName`) and `backend/services/input_file_name.py` (`input_file_name`), which work the same way. With no kept name, the card falls back to the file's own name unless that is a stored hash. That covers a quick-run temp node or an agent pointing at `/Users/me/talk.wav`. An upload saved before this change shows nothing, not a hash.
- **Card.** Audio and Document Input draw one muted line, `.model-node__file-name`, right where Image Input draws its picture (under the header). It uses the same rule as the moodboard line (`.model-node__board-line`: 11px, #888, the Slava Restraint label size and ink), so it adds no new look, plus `nowrap`/ellipsis as a fallback. The full name is in `title`. Image Input is unchanged: it shows the picture, and the brief said to leave it alone unless the shared helper was the obvious place.
- **Middle truncation** is one shared helper, `middleTruncate(name, max)` in `lib/fileName.ts`. The repo had none: every existing cut is at the end (`structuredValue.ts`, `StructuredValuePreview`). It counts characters, not UTF-16 units. It keeps an extension of up to 8 characters (dot included). A name with no extension, a leading-dot name, or an "extension" too long to be one keeps its start and its last third.
- **Decision for GM: the card's budget is 28 characters, not GM's 18.** GM's example "quarterly-rep….pdf" is exactly what the helper gives at 18 (pinned by a test). An 18-character cut on a 200-240px card wastes about a third of the line, so the card uses 28: "quarterly-report-final-….pdf". If GM wants 18, it is the one `CARD_FILE_NAME_CHARS` constant.
- **Palette extract.** The upload now goes through `apiRequest` with the heading `Couldn't upload ${quoted(file.name)}.`. A failure becomes `notify(failureMessage(err, heading), 'error')`, as the file control does. Extraction moved out of the Inspector into `lib/paletteExtract.ts` and returns `{ok: true, colors} | {ok: false, reason: 'decode' | 'transparent' | 'other'}`. The notice puts the reason on its own line under the heading, the way #188's drop notice does (`heading\nreason`, `white-space: pre-line`). "Extracting…" ends in `finally`.
- **How the two reasons are told apart without guessing.** The image is now decoded from the person's own picked file (an object URL), not refetched from the upload's URL. A failed load can then only be a failed decode, never the network. That gives `decode`. `transparent` means every pixel has alpha 0. An image too faint to read (every pixel under the 128 alpha cut, but not all clear), no 2d context, a zero-size image or any exception get `other`, so the notice shows the heading alone. The upload still happens first, as before, but nothing reads its result now (open item below).
- **Agents.** Palette: no new tool. `cinema-color`'s `palette` is a declared param (backend `data/node_definitions.json`), so agents set swatches with `edit_canvas` params (`{"palette": ["#c85a28", …]}`) or set `source_image`. File name: `look_at_canvas` and `get_project` were not showing it. `_` params are dropped from agent reads (`selection_context._safe_value`) and `filePath` is the hash. Each node entry now has `fileName` when one is kept (`agent_presence.redacted_node`). `nebula look` / `nebula project show` print it as `file: "…"`. `upload_file` documents the `filename` it already returned. Docs: `docs/MCP-SETUP.md` (upload_file, look_at_canvas) and `skills/nebula/SKILL.md` (`nebula upload`).
- **Tradeoff.** `validate_file_references` checks every string in params as a possible path, so the kept name is checked too. A name that resolves to a protected file from the backend's working directory would be refused, as a prompt with that text already is. The only realistic case is an uploaded text file named `settings.json` while the backend runs from the repo root. I did not change the security check; I'm flagging it here.

## Coordinator changes after the lane

- **The kept name isn't a file reference.** `validate_file_references` walks every string in params as a possible path. The new `_fileName` would therefore have made an upload named like a protected file unrunnable: a text file called `settings.json`, while the backend runs from the repo root, would have been refused on node creation and run. `_fileName` is display text and nothing reads it as a path, so the walk skips that key. The stored file's own `filePath` is still checked. The test is `test_file_access.py::test_kept_upload_name_is_not_a_file_reference`, which failed first.
- **The palette extract uploads nothing.** The colours come from the picked file, so the upload only stored a copy in output/ that nothing read. It is removed. A file the browser can't decode gets GM's "Couldn't find colors in “name”." with "Nebula can't read this image. Try a PNG or JPEG.", which is better than the backend's 415 line. The test "reads the picked file itself and uploads nothing" replaces the upload-failure case.
- **The 415 line reads as a sentence.** `/api/uploads` now refuses with GM's types line, "Nebula takes images, video, audio, PDFs and text files.", in place of "Only image, video, audio or document (PDF/text) files are accepted" (no full stop). The canvas shows it after "Couldn't upload “name”.", and agents see the same line.
- **Open, for GM - Design:** the card allows 28 characters (GM's example implies 18; the constant is `CARD_FILE_NAME_CHARS`). Should Image Input get the name line too? Today it shows only the picture.
