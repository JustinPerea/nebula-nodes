# 2026-10-21 — A Replicate node's output port is typed from the model, and its run fills it

Branch `fix/replicate-video-audio-ports`, from origin/main `8e654825` (after #143). Uncommitted (the coordinator commits). No paid provider call, no package installed, no frontend file changed in the first pass (the review changed `frontend/src/store/graphStore.ts` and its test).

- **What changed and why.** #143's notes left this open ("needs Justin's call"): a Replicate model's output schema for a file is a plain `uri` string whatever the file is, so `universal_ports.replicate_output` gave every file-output model an Image `image` port, while the run named its output by the returned file (`video`, `audio`, ...). The engine passes outputs by handle name, so on a video or audio model the declared `image` port got nothing, and since #132 a wire from `video`/`audio` was refused. I have no quote from Justin in this session; the brief chose "type the port from the model's metadata, and the run fills the declared port", and that is what's built:
  - `services/universal_ports.replicate_file_media` types a file output before any run, in this order: a content hint in the output schema (on `items` first for a list, then the output): `contentMediaType`, an `x-` key holding a MIME type or a short extension, or a MIME type / file extension written in the description or title; else the file the model's `default_example` run returned (its URL's extension, or a data URI's MIME type; a list by its first file); else `image` with `typeUnconfirmed: true`. Ports: `video` (Video), `audio` (Audio), `image` (Image), `svg` (SVG), `mesh` (Mesh); text outputs stay `text`.
  - `routes/replicate_proxy.get_model_schema` now keeps `default_example_output` from the model object it already reads (`GET /v1/models/{owner}/{name}`), cut down (a URL up to 2,048 characters, a data URI's header only, 200 characters of text, 8 list items, two levels). No new call: the route still makes its same two reads (a test pins the URLs).
  - One extension table: `services/media_types.py` (new, imports nothing from the backend so the MCP server can use it). `services/output.py`'s `_MEDIA_EXTENSIONS` is now that table.
  - `handlers/replicate_universal._fill_declared_port`: a configured node's run puts the output under its declared port. A Text port takes the output as text (a URL string too). A file port takes a file of the same type, or one whose type can't be told (a URL with no telling extension). Anything else (a `.png` from a `video` port, text from a file port, an inline media file from a Text port) fails the run: "acme/clipmaker returned an Image file, but this node's output `video` is Video (typed from the model's data before the run; ...), so nothing was passed on. The result is still on Replicate (prediction ...)". A node never configured keeps `_infer_output_type`'s naming, unchanged.
  - Agents: `model_schema` (ports from `universal_ports`, plus a `note` when a type is unconfirmed), an edit's `modelPorts`/`modelPortNotes` (the same note), `look_at_canvas` (`ports.unconfirmed: [ids]` when present), `describe_node`'s `modelPorts` sentence, and `nebula apply` (prints `modelPortNotes` already). Docs: docs/MCP-SETUP.md (three places), skills/nebula/SKILL.md, both copies of the project's `replicate` skill (the "Open issue" and "Don't rely on chaining from video/audio" lines are gone; a new "Output port typing" section replaces the old inference table, which stays for never-configured nodes), docs/api-guides/replicate.md, docs/model-providers/replicate-openrouter-nous/universal.md.
