- **Q61, who may stop a run.**
  - *Recorded where runs are tracked.* `ExecutionRunRecord` has `started_by` and `stopped_by` (services/execution_runs.py). `register()` takes `started_by=`, or asks a starter source main.py installs (`execution_runs.set_starter_source(_run_party)`), which reads the request's headers as the journal does (`actor_for_headers`, an unnamed request with an agent marker counted as an agent). So the four register sites (`/api/execute`, `/api/execute-node`, the cinema shot route, `/api/graph/run`) are unchanged: the route bodies other lanes are editing for run billing don't move.
  - *The rule is one function*, `stop_refusal(started_by, caller_is_person=)`: the person stops anything; anyone else stops anything but the person's run. `DELETE /api/executions/{id}` calls `_refuse_stopping_the_persons_run` first, before `record_cancel_intent`, so a refused Stop leaves no durable intent and no other backend's watcher stops the run. Allowed Stops run the old code unchanged.
  - *Refusal* is a `PersonGateError` 403: code `agent_refused` for a caller with an agent marker, `person_required` for an unnamed one (the canvas shows its "not connected as you" note for that code, which is right for a tab without the token). Message: "The person started this run, so only they can stop it: ask them to press Stop in Nebula (the toolbar, or the run in Run history). Agents stop only runs an agent started." `cancel_run`'s docstring and the INSTRUCTIONS say the same.
  - *Anonymous callers (decided).* No agent marker and no person token: the CLI without NEBULA_AGENT_NAME, curl, a tab not connected as the person. Their Stop is not the person's, so they can't stop the person's run; their runs count as an agent's (nothing proves the person started them), so any agent, the CLI and the person stop those. For someone using the CLI by hand: `nebula cancel` still stops what the CLI or an agent started; on a run started from the canvas it exits 1 with the message above (checked live). A tab not connected as the person starts anonymous runs and stops them as before.
  - *Edges.* A run ID no run here has used keeps the pre-admission tombstone for anyone (as before). A run whose POST has noted its starter in the journal but not yet registered is judged by the journal (`canvas_events.run_actor`), closing that window. A run that already ended answers its status to anyone (nothing left to stop; otherwise `nebula cancel` would tell the agent to ask for Stop on a finished run).
  - *Journal (found while building).* `run.cancelled` was attributed to the run's starter, so when the person stopped an agent's run, that agent's `wait_for_canvas_change` skipped the event as its own. It is now attributed to whoever stopped it (`stopped_by`, the first allowed Stop), with `data.startedBy {kind, name}`; a Stop another backend recorded has no stopper here and keeps the starter. docs/MCP-SETUP.md's event table says so.
  - *Existing test changed:* `test_canvas_stop_syncs_recovery_params_before_cancelled_event` started a run as the person and stopped it with no headers; it now stops it inside `request_headers_scope(PERSON)`, as the canvas sends its token on DELETE (frontend `apiFetch` adds `X-Nebula-Person` to every non-GET).
- **U10, model catalogs.** `model_catalog(provider, query, limit)` over `/api/openrouter/models`, `/api/nous/models`, `/api/quiver/models`; `model_schema(provider, model_id)` over `/api/replicate/schema/{owner}/{name}` (Replicate) or the catalog row (others). Both `readOnlyHint` + `openWorldHint`, through `_canvas_call` (the routes the Inspector uses). Replicate has no list route, so `model_catalog("replicate")` points at `model_schema`. `model_schema` for Replicate splits inputs the way `graphStore.fetchReplicateSchemaAndConfigure` does (`x-uploadable` or `format: uri` is a port, the rest params) as `inputs[].port`; that mirrors frontend reading logic in the tool's answer only, it configures nothing.
- **U10 follow-up: configuring a dynamic node's ports is frontend-only (CONFIRMED, not built).**
  - Backend: cli_graph nodes keep only definitionId/params/outputs; `_cli_node_to_rf` (main.py) sends universal nodes with the definition's ports and `dynamicParams: []`. Port validation (`services/port_contracts.py` `_declared_port`) treats a direction as dynamic only when the definition declares no ports there.
  - Checked on /api/graph/apply (scratch probe and the live MCP check): Replicate (no declared ports) accepts a wire to any input name, and the handler sends inputs by handle name, so an agent can wire `input_image` and set `prompt`/`aspect_ratio` as params; that runs. OpenRouter refuses `images` ("Valid inputPorts: ['messages']") and an `image` output; Nous refuses an `image` output; `_output_image` and `_version_id` are refused as internal params. So an agent can't build an OpenRouter vision or image-output node at all.
  - Canvas (browser check; screenshot in the lane report): the agent-built Replicate node shows no ports and its wire (n1.image to n2.input_image) isn't drawn, though `/api/graph` holds it as e1. The canvas only draws ports after the Inspector's picker runs `configureOpenRouterModel` / `fetchReplicateSchemaAndConfigure`, which keep them in the browser.
  - *Fix it needs:* one backend function deriving a universal node's ports from its params and the provider's model data (OpenRouter/Nous modalities; Replicate schema), used by `_cli_node_to_rf` (send real ports), `port_contracts._declared_port` (validate against them) and the frontend's two configure actions (call a backend route instead of computing locally); store what it needs server-side (the Replicate version and input split, `_output_image`) as canvas-owned params set by that route, not by agents. Then `edit_canvas` changing `model`/`model_id` reconfigures the node for agents and the person alike, and `configure_dynamic_node` isn't needed as its own tool.
- **U14, Krea discovery for outside agents.** Chose to fold the calls into the `nebula` server (the audit's second shape) over registering `nebula_krea` in agent_connect and ACP: outside agents get one server, Settings > Connect your agent (GM - Design's demo screen) doesn't change, and both paths share `KREA_READONLY_TOOLS` and the same routes (`GET /api/krea/tools`, `POST /api/krea/tools/call` → `KreaConnector.call_readonly`), so nothing can drift.
