# 2026-10-21 — Prices measured from the input file (SeedVR2, FLUX Video Upscale and Edit)

Branch `feat/price-from-input-size`, based on `main` at 6a706bea.

- **What changed and why.** GM - Design hit it today: SeedVR2 Upscale had no list price, so `nebula quick` and MCP runs of it were always refused ("Nebula has no list price… can't check this run against the spending limits") and every run needed a canvas proposal. fal prices it "$0.001 per megapixel", which depends on the input image's size, so a fixed row would have been a guess. The fix is structural: a price entry can now carry `sizing`, and its `multiplyBy` can read quantities measured from the run's input file when the run is checked: `(input megapixels)`, `(output megapixels)`, `(larger megapixels)`, `(source seconds)`, `(source frames)`. The brief asked for exactly this ("the structural fix, not a guessed row").
- **Where the size comes from** (`backend/services/input_sizes.py`). Only the file the run will send, and only its header: Pillow's lazy open for images, a synchronous ffprobe of the header for clips (`input_sizes._probe_video`, same local-only input policy as the other ffprobe calls, reusing `ffmpeg._media_input_args`). It lives in `input_sizes.py`, not `services/ffmpeg.py`: the first full run failed `tests/test_node_readiness.py` because a process spawn in `services.ffmpeg` made every utility handler that imports it read as able to reach a paid API. An Image Input or Video Input in the run gives its file; `nebula quick`'s temp input node is one of those; a node outside the run gives the output it already has (a proposal's cached ancestor). A node that runs in the same request makes its output during the run, so the node it feeds stays unpriced. Outside URLs are never fetched (a test patches httpx and urllib to fail if they are). Results are cached by path, mtime and size.
- **Entries added.** `seedvr2-upscale`: $0.001 per megapixel, `unconfirmed`, of the larger of input and output, rounded up to a whole megapixel (Nebula's assumption, said in the notes), target mode computed both ways (short side = target, long side = target) and the larger taken. `seedvr-video-upscale`: fal's page (fetched today) says "$0.001 per megapixel of video data (width × height × frames)" of the upscaled video, with a worked example (1920×1080, 121 frames = $0.25) that fixes the megapixel at 1,000,000 px; added as `megapixel-frame`, `unconfirmed` because frames are taken from the source and target mode's side isn't stated.
- **FLUX Video Upscale and Edit [fast].** Their existing rows now resolve: BFL and Replicate upscale per megapixel-second of output (BFL 1,048,576 px a megapixel, as BFL says; Replicate 1,000,000, the side that costs more), Edit on BFL and fal per second. fal's FLUX Video Upscale route stays unpriced: it bills by output tier and fal doesn't say where tiers split, so even a measured clip can't pick a tier. `(output tier)` is the one run-time variable that is never measured.
- **Decisions not in the spec.**
  - Seconds round up to a whole second on the FLUX video routes. The vendors say "per second of output" but not how a part second bills, so this is the costlier side. BFL's megapixels per frame are not rounded, since BFL states that formula exactly.
  - SeedVR2 Video isn't rounded: fal's example works out exactly at 1,000,000 px.
  - Two wires into the measured port, or an input from a batch or a list, measure as unknown rather than guessed.
  - The canvas measures through a new `POST /api/pricing/input-sizes` route (output-store files only, up to 64 refs) instead of reading sizes in the browser, so Python's Pillow/ffprobe is the one source of sizes. The agent check also reads files elsewhere that the run may read (`require_allowed_path`), since that's what the handler sends anyway.
  - The refusal for an unknown size says what works: wire an Image Input (or Video Input) holding the file into the node, run it with `nebula quick <node type> --input <port>=<file>`, or propose it. "Run the upstream node first" alone would not help a direct run, because a node's run always includes everything feeding it (`get_subgraph`), so the upstream runs again in that same request. A proposal made after the upstream has run is priced from its output, and the message says so.
  - `find_nodes` and `nebula context` show `"by input size"` as the price for such a node (with `priceNote` in find_nodes); `describe_node` adds `price.byInputSize`, `multiplyBy` and `price.unconfirmed`; a route has `priceBy`. `nebula info` gains a PRICE line (it had no price before).
  - Proposal estimates add `awaitingInput` (only when non-empty, so existing estimate shapes are unchanged).
- **Tradeoffs.**
  - The video probe is synchronous inside the async run routes (up to 10 s timeout, typically tens of milliseconds) because the spend check is synchronous. Only sized nodes with a local clip trigger it.
  - The canvas confirm reads sizes already fetched for the chip. If the person clicks Run before the size arrives, the node is unpriced in the confirm (as unpriced nodes always were) rather than blocking the click.
  - The chip for a generator → SeedVR2 chain still reads unpriced ("Priced when its input is known"), matching the backend rule: the generator reruns in that run.
- **Surprises.** On today's `main` the TS estimator would have priced a `(larger megapixels)` entry with no size at $0.001 (one unit), since only the three old run-time names were in its list; the new shared case "with no measured input it is unpriced" caught that. `to_execute_format()` drops node outputs, so the proposal estimate now takes the staged graph's nodes (with outputs) separately.

## Security fix (2026-10-21)

Two findings from the security review, fixed before the PR opens. This section supersedes two lines above: sizes are no longer cached by path, mtime and size only, and the agent check no longer reads files outside the output folder.

- **Finding 1, the file can change after the check (TOCTOU).** The spend check measured a file when the run was checked, but the handler reads it later (other nodes may run first), so an agent could pass a small clip, get the run approved, then swap in a long one. Now only inputs no API-only agent can change are measured (`services/input_sizes.py` `_locate`, `measure`): an inline `data:` image (it lives in the run's params) or a file in `OUTPUT_ROOT` whose path as given is inside with no `..` part and whose resolved path is inside too, that isn't a dot-name (`.x.part`) and isn't in a run folder Nebula is still writing. Everything else gets the new `outside` reason. The refusal (`services/agent_spend.py`) says the file is outside Nebula's output folder and could change after the check, so Nebula doesn't price a run from it, and names the way in: `nebula upload <file>` (MCP `upload_file`), then wire that input and run it; image ports also get the `nebula quick` line. The cache key is now `(path, st_dev, st_ino, st_size, st_mtime_ns, st_ctime_ns, kind)`, so a rewrite that keeps the size and mtime still misses. The canvas route `/api/pricing/input-sizes` uses the same rule (`measure(..., inline=False)`), so the chip and the check agree.
- **Premise audit: nothing an API-only agent runs can create, overwrite or rename over a file in `OUTPUT_ROOT`.** Checked every writer:
  - Claude profile: `services/agent_profiles.py:66` `CLAUDE_TOOLS` is Bash/Read/Glob/Grep and `:74` `CLAUDE_ALLOW_RULES` allows only `Bash(nebula *)`, no write tools. But `nebula save <path>` (`cli/commands/graph.py:66`) replaced any path the caller named, store files included. Fixed: it refuses an existing file that isn't a saved graph (`_is_saved_graph`, line 55).
  - Codex profile: the `:workspace` base lets the agent write its cwd, `/tmp` and `$TMPDIR` (checked with `codex sandbox`, codex-cli 0.163.0). `OUTPUT_ROOT` isn't under those today, but a person's output folder setting could be. Fixed: `codex_filesystem_args(output_root=...)` (`agent_profiles.py:403`, passed from `codex_session.py:406`) adds both spellings of the output folder as `"read"`, which overrides the base (checked: `touch`, `ln` and `mv` into it were all denied), and refuses a workdir that overlaps it.
  - Uploads (`main.py:2567`) and imported images (`main.py:1712`) wrote sha256-named files in place, so a second upload of the same name rewrote a file being read. Now `services/output.py` `write_new_file` writes `.{name}.{uuid}.part` with `"xb"`, then `os.link`s it to the name (never replaces an existing file).
  - Export (`main.py:15144`): copies to a dot-name, then links to a fresh collision-avoided name. The export folder is a person setting.
  - Archive (`main.py:2220`): moved run folders aside with a suffix; it now skips folders still being written (`is_being_written`, line 2250).
  - Restore (`main.py:1234` area): writes a fresh `restored-<uuid>` folder via `.part` with `"xb"` then replace, and rejects duplicates. Fine, since dot-names aren't measured.
  - Run folders: `create_run_dir` registers each as live; `seal_run_dir` closes it at the end of `execute_graph` (`execution/engine.py:999`), a render job (`services/render_jobs.py:66`, sealed only on success) and an edit preview (`routes/video_edit_preview.py:78`). Engine-cached artifacts go `.part` then replace inside run folders.
  - Not in the store, so not measurable: thumbnails (state dir), moodboard, character, preset and Commons roots under `~/.nebula`, Commons fetch (`cli/commands/commons.py:57-69`, a fresh temp name in the workspace), paper sources (`"xb"` hash names). Convert-to-GLB writes `.preview.glb` beside its source, which isn't an image or clip. Skill install and `mcp connect` write home config only. The MCP-side modules write no local files.
  - No MCP tool or CLI command added a clip to the store (images under 20 MB were imported automatically). Added: MCP `upload_file` (`mcp_server.py:875`, also in `krea_agent_mcp.NEBULA_MCP_TOOLS`) and `nebula upload <file>` (`cli/commands/upload.py`), both through `backend/upload_client.py`, which reads with `require_allowed_path` (a chat turn's token keeps it to its workspace), opens without following links, caps at 500 MB and posts to `/api/uploads` (create_node), the canvas's own route. That route now returns `nodeType`.
- **Finding 2, the probe and the provider can read the file differently.** `_probe_video` now looks at every video stream and measures only when exactly one isn't an attached picture (cover art). A second pass reads that stream's demuxed packets (demux only, nothing decoded): frames = max(packet count, header `nb_frames`, ceil(seconds x avg fps)), seconds = max(stream duration, format duration, packet span). A packet with "New Extradata" or "Param Change" side data leaves it unmeasured. The probe keeps the shared input policy (local files, allow-listed single-file containers, `-enable_drefs 0`, `-use_absolute_path 0`, scrubbed env) and stays out of `services/ffmpeg.py` so handlers can't reach a process spawn through it. Images: one with more than one frame or size (`n_frames`, `info["sizes"]`: GIF, APNG, animated WebP, TIFF pages, ICO/ICNS, MPO) is unmeasured.
- **Frame rate.** `avg_frame_rate`, not `r_frame_rate`. ffmpeg's `r_frame_rate` is a guess at the base rate and on a phone's variable-rate clip is often the container timescale (600, 120), which would multiply the frames many times over and refuse ordinary runs. `avg_frame_rate` matches a constant-rate clip's count, and the packet count is in the same max, so a low header can't bring the count under what the demuxer delivers.
- **Known limit.** A size change inside the coded bitstream (an in-band H.264/HEVC SPS, a VP9 resize) shows only on decode. Checked: a concat of a 64x48 and a 640x480 H.264 clip has a 64x48 header and no packet side data. Such a clip is measured at its header size. Documented in `docs/MCP-SETUP.md` ("Spending limits") and `docs/MODEL-PRICING.md`. Closing it means decoding every frame, which a price check shouldn't do.
- **Off the event loop.** Measuring reads files and can run ffprobe for many seconds, so every pricing path goes through `asyncio.to_thread`: `input_sizes.measure_run`, `main._measure_run_inputs` (run, execute, execute_node, cinema shot, quick, run_graph), `_measure_proposal_inputs` (proposal create and estimate) and the canvas route. `run_input_sizes` raises if called on a running loop (`_off_loop`). One deadline of `SIZE_PROBE_TIMEOUT_SECONDS = 60` covers both passes; past it the clip is unmeasured. Because the measure now awaits, `_measure_run_inputs` reads the workspace revision before and checks it after, so a project switch during the probe answers 409 rather than pricing the wrong graph. `_require_spend_approval` takes `measured` as a required argument and raises for an agent run without one, so no path can skip measuring.
- **Decisions.** Refuse rather than copy an outside file at check time: a silent copy would change which file the run reads. `nebula save` refuses instead of writing beside: the caller named the path. The upload tool is `_EDIT` (it adds a node), not a spend path, so agents get it.
- **Tradeoffs.** Reading every packet means reading the whole file from disk (a few seconds for a multi-gigabyte clip); the 60 s cap bounds it. A run whose input sits in the workspace now needs one `nebula upload` first.
- **Surprises.** Pillow merges identical GIF frames, so the multi-frame tests use frames of different colours. ffmpeg isn't on PATH under `iso.sh`, so its tests skip unless PATH includes `/opt/homebrew/bin`.
