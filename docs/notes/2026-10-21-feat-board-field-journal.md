# 2026-10-21 — A board's own fields are journaled (`board.fields`)

Branch `feat/board-field-journal` from origin/main a330dc64.

- **What changed and why.** Justin's answer to Q91: "a) Yes, every field change, with the field names but none of your text." Before this, a change to a board's own fields (Direction, Avoid, pinned colours, strength, mode, clash mode, Send notes, a rename, the hand-written brief) made no journal event, so an agent waiting on a board (`wait_for_canvas_change`, `nebula watch`) heard of the person's Direction edit only when its wait ran out (25 s at most per poll). Now every board write that changes a field journals one `board.fields` event: data `{boardId, boardName, scope, fields}`, `fields` the names that changed in a fixed order (`name`, `notes`, `mode`, `strength`, `direction`, `avoid`, `pinnedColors`, `clashMode`, `colorChoices`, `sendNotes`, `briefOverride`), the actor the journal's usual one. Summary: "changed Direction and the Avoid list on board Good Machines" (the CLI's watch line puts the actor before it: "Person  changed ...").
- **One place.** Every board write goes through two routes, `PUT /api/moodboards/{id}` and `POST .../edits` (whose `restore` op is every undo: the Studio's Cmd+Z, `moodboard_update(**previous)`, `nebula moodboard set --restore`, `moodboard_edit` with undo ops). MCP and the CLI both call those routes (`moodboard_client.py`). Both routes already called `main._journal_board_change`, so the journaling sits there, built from the same `moodboard_edits.diff` that makes each write's undo. The accepted Send notes proposal (`services/asset_proposals.py`, still on `feat/mcp-asset-proposals-commons`, not on main) calls `update_moodboard` in process under the person's headers, so it lands in the same place; a test calls the route that way. Commons intake only reads boards.
- **Never a value.** No Direction, Avoid, notes or brief text, no colour, no strength number, and not which way Send notes went: names only, for every field. Tests put sentinel text in each field and check the serialized journal holds none of it.
- **Decision: the board's notes moved from `board.noted` to `board.fields`.** Before, a change to the board's own notes was `board.noted` with no image refs ("changed the notes of board Dusk"). Keeping that and also listing `notes` in `board.fields` would have made two events for one write; leaving `notes` out of `board.fields` would have left out a field Justin's answer covers. So `board.noted` is now an image's notes only. Docs (MCP-SETUP, contract 07, the canvas plan) say so. A waiter on the `board` group sees no difference; one filtering on exactly `board.noted` for board notes would now need `board.fields`.
- **Decision: the cover stays `board.cover`.** It names an image ("made #3 the cover"), has refs and its own kind already, so `coverImageId` isn't in `board.fields`.
- **Decision: two events for a mixed write.** A PUT that changes images and fields (an older client) journals the image event first, then `board.fields`. Each event is complete alone; an edit batch's `say` goes on both.
- **Decision: long lists.** A summary names up to 3 fields and "N more fields" past 4, so the 200-character summary cap never cuts the board's name off; `data.fields` always has them all.
- **The Agent log.** It is fed by `agentPresence` lines for an agent's own writes, not by the journal, and that already named field changes. It now uses the same words (`moodboard_edits.field_label`, shared), so an agent's field-only change reads exactly as the journal summary, capitalised. One difference, on purpose: the Agent log still says "turned Send notes to generators off" (the line as before; an agent can only turn it off), while the journal says "changed Send notes to generators". The person's own writes still add no Agent log line (existing rule). The frontend has no kind-to-text or icon map, so no frontend file changed.
- **Behaviour change in pinned tests.** `test_moodboard_agent_actions` ("Changed the notes of board Dusk" is now "Changed the board's notes on board Dusk") and two `test_moodboard_edits` journal-order tests (board notes and a rename now add a `board.fields` event). Updated on purpose, with comments.
- **Agent support.** `board.fields` is in `EVENT_KINDS` (so `kinds=board` and `kinds=board.fields` both match), the MCP `wait_for_canvas_change` and `moodboard_update` docstrings name it, `docs/MCP-SETUP.md` has a table row and a line in the moodboards section, `skills/nebula/SKILL.md` says `nebula watch --kinds board` sees it and that it never carries values. The MCP INSTRUCTIONS list no event kinds, so they didn't change.
- **Tests first.** `backend/tests/test_moodboard_field_journal.py` (21 tests). On the code before the change, 18 failed: no `board.fields` kind (the kind test, and the MCP waiter got a 422 "unknown event kind 'board.fields'"), no event for any field write (the Studio PUT, every-field PUT, notes, mixed PUT, MCP `moodboard_update` and its undo, `moodboard_edit` restore, `nebula moodboard set` and `--restore`, the person's restore, the in-process proposal path, single-field writes), the long-poll waiter ran to its timeout, and the watch line and Agent-log-equals-summary checks found nothing. 3 passed already and still pass: a no-op write journals nothing, a cover pick stays `board.cover`, and a private note label never reaches the journal.
- **Live check.** Isolated backend on 8819 (temp HOME, every NEBULA_* root in scratch, `env -i`, no keys) with a per-launch person token, Vite on 5819 with `VITE_NEBULA_BACKEND_PORT=8819` (checked the proxy read the isolated project list first). Puppeteer at 1440x900 and 1280x800, CDP `Network.setBlockedURLs` for 8000-8010 and 5173 plus a dead proxy that only lets 5819 and 8819 through; canary fetches to 8000, 8123 and 5173 were refused. A real MCP stdio session (`mcp_server.py --url http://127.0.0.1:8819`, as "Claude Code") sat in `wait_for_canvas_change(kinds=["board"])`; I typed in Direction in Moodboard Studio as the person; the wait returned about 1 s after typing began (the Studio sends 600 ms after the last key) with one `board.fields` event, actor person, `fields: ["direction"]`, summary "changed Direction on board Good Machines", and no typed text anywhere in the answer. Then the MCP session added an Avoid item: one `board.fields` event `["avoid"]` by Claude Code, and the canvas's Agent log showed "Claude Code · Changed the Avoid list on board Good Machines". Sending the same Avoid item again (an earlier run) changed nothing and journaled nothing. Blocked requests: 0 to 8000-8010 or 5173 from the app; the only failed request was Google Fonts through the dead proxy.
- **Not journaled (unchanged).** Making a board, Analyze, Keep the brief, move, delete and restore from Recently deleted have no journal event (they are Agent log lines for agents only, as before). Restoring a deleted board brings its fields back whole but isn't a field change; if Justin wants it journaled it would be its own kind.
