- **What.**
  - *Tools* (backend/mcp_server.py, a new section before `_parse_args`): `rename_project` (PUT /api/projects/{id} `{name}`, the header's rename; returns `previousName`, renaming back undoes it), `get_project` (GET /api/projects/{id}?view=agent), `get_settings` (GET /api/settings, shaped: key names to booleans, routing, executionMode, batchSizeCap, exportFolder, kreaConnectionMode), `provider_status(refresh)` (GET /api/health/providers and GET /api/krea/connection). `list_projects` rows gain `cover`; `list_trash` takes `scope` and `project_id` (id or "current"); `wait_for_canvas_change` takes `journal`; `look_at_canvas`'s docstring names `proposals` and `providerHolds`; `get_run`'s names canvas runs. All four are in `NEBULA_MCP_TOOLS`, docs/MCP-SETUP.md and INSTRUCTIONS.
  - *Agent view of a saved project* (services/project_view.py): every node goes through `agent_presence.redacted_node`, factored out of `AgentPresence.snapshot` (same output; `output_availability` too), so a closed project's nodes equal what look_at_canvas showed while it was open (a test compares them field by field). Run history: newest 20, each with status, timing, `nodeIds` and output availability, never recipe params or output values. Cover through `_safe_value` (signed links keep their path).
  - *Journal kinds* (services/canvas_events.py): `project.created/renamed/deleted/restored`, written by `_journal_project_change` next to each `_broadcast_projects_changed` call that makes, renames, deletes or restores (recovered copies count as made). `_save_project` returns `previousName` when the body has a name; a rename is journaled only when the name changed. `provider.hold` with `hold` (recovery, startAmbiguity) and `change` (held, cleared): held in `_emit_and_sync`'s two paid-start branches (actor: whoever started the run), cleared in the two DELETE routes when something was removed.
  - *Canvas runs in get_run* (services/run_reports.py, fed by `_emit_and_sync` just before the broadcast): per run, per node state, outputs, error, latest progress, streamed text (4,000 characters). `GET /api/graph/runs/{id}` falls back to it plus `execution_runs` when `_cli_runs` doesn't know the id, answering in the CLI-run shape with `source: "canvas"`, `startedBy` and `nodes`. A CLI run still going also carries `nodes` and `startedBy`; a finished CLI run answers exactly as before (test_cli_run_errors compares them).
  - *look_at_canvas `providerHolds`*: `{recoveries, startAmbiguities}`, the two lists graph export has, fields picked explicitly.
  - *Frontend* (store/projectStore.ts): a `projectsChanged` `renamed` for the open project lists again, and every listing now refreshes `activeProject` from the list, so the canvas header shows an agent's rename without a reload. Autosaves (`saved`) and other projects' renames don't list.
- **Decisions not in the spec.**
  - *`get_project` redacts on the server* (`?view=agent` on the same route), because node names need the registry and the MCP process shouldn't load it or a store. The raw route is unchanged for the canvas.
  - *Krea's `authorizationUrl` is left out* of `provider_status` (`signInPending: true` instead): the sign-in link is the person's to open.
  - *`provider_status` is `openWorldHint=True` with or without `refresh`*: an expired 5-minute cache probes providers anyway (free, read-only calls). It runs in the wait pool, since probes can take 10 s.
  - *`get_settings.configured`* uses the settings' key names (`OPENAI_API_KEY`), the names find_nodes' `missing` uses. Settings outside the audit's list (outputPath, favorites, zoom telemetry, spend caps) stay out; get_spend_limits covers the caps.
  - *`startedBy`* is `actor_record` of the journal's run actor, so the person reads as `{kind: "person", name: "You"}`.
