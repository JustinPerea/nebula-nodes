# Cinema motion handoff decisions — 2026-10-08

- `POST /api/cinema/send-to-motion` owns only `{nodeId, shotId, expectedImageUrl}`. It validates a current Cinema node, one exact shot ID, settled `done` output, and an `Image` output port whose value agrees with both the shot preview and the requested image. It returns only the confirmed frontend target node and exact typed edge.
- The action creates a `veo-3` node at the canonical source position plus 360 horizontal pixels, with catalog defaults following the same shared/fal/direct precedence as ordinary frontend node creation. It connects `shot_<shotId>` to `image` and never executes or checks provider credentials.
- Local absolute output paths, portable output URLs and loopback browser preview origins compare through `portable_output_ref`. Remote HTTP image URLs remain exact opaque identities, including signed query strings; nothing is downloaded. Malformed/escaping local references fail before mutation.
- Existing exact connections to `veo-3:image` are checked with the shared port contract. When several valid targets exist, the first in persisted graph edge order is reused. Target parameters, earlier outputs, source variations, other nodes and all earlier connections remain intact.
- Validation, graph cloning, connection validation and durable `replace_with` run before the first await. Concurrent requests in the server event loop see the committed exact edge. A failed connection or durable write leaves both live state and disk unchanged; a lost broadcast/HTTP acknowledgement after commit is safe to retry, including after restart, without a separate handoff registry.
- `CLIGraph.connect` normally allocates an edge ID from list length, which can collide after earlier edge deletion. This endpoint advances its staged edge ID until unique before commit; it does not change general graph behavior.
- Unpositioned source/target nodes use the existing graph export layout fallback. No graph replacement/import is used to adopt frontend state, so unrelated authored state and run ownership cannot be overwritten by this handoff.
- Scope ceiling: there is no graph incarnation/revision token. A replacement with the same Cinema ID, same shot ID and same exact image is indistinguishable from the original request. This action checks current ownership and media identity at commit time; it does not promise a persistent identity across arbitrary same-ID/same-media imports. Concurrent safety is within the current server event loop, matching the app's canonical in-memory graph ownership, rather than a new multi-worker graph transaction protocol.
- Native review exposed a canonical export gap: Cinema edges were styled as `Any` because the exporter only read static catalog output ports, while Cinema declares shot ports from the saved scene. The export loop now uses the existing `cinema_output_ports` contract for Cinema sources. Valid shot edges hydrate as `Image` in both GET export and authoritative graphSync; unknown shot handles retain `Any`, and other definitions keep their existing type lookup. A real export/broadcast regression covers all three cases.

Validation uses a real `CLIGraph` with private temporary persistence and the API route. It covers normal create/retry, acknowledgement loss and reload, overlap while the first broadcast waits, stale source/shot/media rejection, exact port agreement, local/remote reference identity, connection/write rollback, reused target results and deterministic reuse. Execution, provider settings and handler discovery are guarded to fail if called. All 40 new handoff cases passed together with existing Cinema authoring, Cinema port-contract and CLI API coverage: 209 tests passed, with two existing FastAPI lifespan deprecation warnings. `git diff --check` passed. The initial overlap fixture used a non-local HTTP origin and was correctly rejected by the existing local request guard; using loopback exercises the intended concurrency path without bypassing that guard. The canonical export/broadcast regression first reproduced the native `Any`-edge failure and passed after the narrow exporter fix.
