# Cinema server persistence decisions — 2026-10-07

- Review reproduced a server-side race: a scene PUT captured before generation completion replaced a newer canonical shot result, variation history and selected variation while leaving the output port unchanged. Frontend echo suppression could hide this until reload.
- Existing Cinema scene parameter PUTs now represent authoring edits. Stable shot IDs preserve exactly the canonical `output`, `variations` and `selectedVariation`, including absence. Prompt, references, base settings and shot order still come from the incoming authoring edit.
- Newly authored shots start with idle output and no imported variations/selection. Graph import, generation merges and the explicit variation-promotion endpoint remain the authoritative paths for installing runtime media.
- Removing a shot also prunes its live output port and downstream edges on the server. Other outputs/edges and immutable run records remain untouched. Structural shot identity validation happens before mutation.
- Regressions use a temporary, synthetic CLIGraph and mock broadcasts/paid guards; no real settings, provider, OAuth, or generation is accessed. This does not add a backend graph revision protocol for arbitrary delayed same-ID requests across graph replacement.
- Follow-up review found the inverse race at whole-scene execution completion: copying the recipe's scene parameters would replace newer authored prompts, uploads and shot order. Cinema terminal parameter sync now installs only each surviving shot's produced `output`; canonical authoring, newly added shots and exact variation/selection history remain in place. Missing/retyped nodes and malformed current scenes do not acquire old recipe authoring.
- Executed-event normalization still returns the full recipe outputs for history, including an artifact for a shot removed during its run. Canonical Cinema ports merge only surviving shot IDs and retain ports for current shots absent from that recipe; obsolete ports are removed. Other handlers and import semantics are unchanged.
- A private execution-only `GraphNode` marker distinguishes shots that actually settled from copied request outputs. The Cinema handler records done/error outputs immediately, so cancellation preserves completed shots without overwriting untouched siblings. Request JSON cannot set the marker, and graph/recipe serialization excludes it.
- Peer review identified partial cancellation could persist the completed shot's scene output while its live port remained old, because the whole-scene ExecutedEvent had not fired. Terminal sync now persists derived done/error ports alongside produced runtime, retaining sibling ports; success/error cancellation regressions verify both scene and port after disk reload.
- Whole-scene cache hits bypass the handler. Their marker uses cached status/error/hash metadata plus the current run's rebound media URL, without installing cached authoring or variation history. Iterator context completion and cancellation copy only this marker alongside the existing parameter copy; other handlers are unchanged.
